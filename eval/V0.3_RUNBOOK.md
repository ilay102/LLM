# v0.3 Eval Runbook — run this in the Codespace (needs live gateway + keys)

The code for **v0.3.0 (corpus)** and **v0.3.1 (LLM cascade verifier)** is built
and pushed on branch `v0.3-quality`. This runbook is the **gate**: it proves
whether the LLM verifier actually beats v0.2.2 before we merge.

Everything below runs in the Codespace (it needs the running gateway, Redis,
and the API keys). Nothing here was runnable on the Windows side.

## What changed

- `eval/corpus_v1.jsonl` — 260-row stratified corpus (was 30). Includes 30
  multi-turn conversations and 30 long-system-prompt/RAG rows the old corpus
  lacked. Build with `python eval/build_corpus.py`.
- `gateway/router/verifier.py` — LLM cascade verifier. Heuristic pre-filter
  (free) + Haiku grader (1-5) on cheap-tier responses. Escalates if score < 3.
- `gateway/router/main.py` — cascade block now calls `verifier.verify()`.
- `scripts/eval_corpus.py` — now handles multi-turn `messages` arrays.
- `eval/run_deterministic.py` — free, judge-free behavior checks for CI.
- `VERIFIER_MODE` env: `off | heuristic | llm` (default `llm`).

## The gate — run in order

```bash
cd /workspaces/LLM
git fetch origin && git checkout v0.3-quality && git pull

# 1. Bring the gateway up with the new code
cd gateway
docker compose up --build -d
sleep 90
curl -s http://localhost:8000/health | python3 -m json.tool

# 2. Unit tests (should now include test_verifier — expect all green)
pip install --user pytest-asyncio==0.24.0 2>&1 | tail -1
pytest -m unit -v 2>&1 | tail -25

# 3. Run the eval THREE ways on the SAME corpus, so we isolate the verifier's
#    effect. Flush cache between runs so cheap answers aren't reused.
cd /workspaces/LLM

run_eval () {
  MODE=$1; OUT=$2
  docker compose -f gateway/docker-compose.yml exec -T redis redis-cli FLUSHDB >/dev/null
  docker compose -f gateway/docker-compose.yml exec -T gateway sh -c "echo verifier=$MODE" >/dev/null 2>&1 || true
  # set VERIFIER_MODE via container env: restart with the override
  VERIFIER_MODE=$MODE docker compose -f gateway/docker-compose.yml up -d --no-deps gateway
  sleep 20
  GATEWAY_URL=http://localhost:8000/v1 GATEWAY_KEY="$GATEWAY_MASTER_KEY" \
    ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
    python3 scripts/eval_corpus.py --limit 60 --results "scripts/$OUT"
}

# NOTE: easiest reliable way to set VERIFIER_MODE is to add it to gateway/.env
# then `docker compose restart gateway`. The helper above is a shortcut; if it
# doesn't pick up the env, just edit .env and restart between runs.

# Run A: verifier OFF (baseline routing only)
#   set VERIFIER_MODE=off in gateway/.env, restart gateway, then:
GATEWAY_URL=http://localhost:8000/v1 GATEWAY_KEY="$GATEWAY_MASTER_KEY" \
  ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  python3 scripts/eval_corpus.py --limit 60 --results scripts/eval_off.jsonl

# Run B: verifier LLM (the new thing)
#   set VERIFIER_MODE=llm in gateway/.env, restart gateway, flush cache, then:
GATEWAY_URL=http://localhost:8000/v1 GATEWAY_KEY="$GATEWAY_MASTER_KEY" \
  ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  python3 scripts/eval_corpus.py --limit 60 --results scripts/eval_llm.jsonl

# 4. Deterministic checks (free, no judge) on the LLM run
python3 eval/run_deterministic.py --results scripts/eval_llm.jsonl --min-pass 0.85

# 5. 3-judge ensemble on BOTH runs to compare quality
#    (point judge_ensemble at each results file; it reads gateway+baseline answers)
ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" OPENAI_API_KEY="$OPENAI_API_KEY" \
  python3 scripts/judge_ensemble.py --results scripts/eval_off.jsonl \
    --label v0.3-off --out-report scripts/q_off.html
ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" OPENAI_API_KEY="$OPENAI_API_KEY" \
  python3 scripts/judge_ensemble.py --results scripts/eval_llm.jsonl \
    --label v0.3-llm --out-report scripts/q_llm.html
```

`judge_ensemble.py` takes `--results`, `--label`, `--out-report`, and
`--out-verdicts` — confirmed present.

## SHIP / PARK decision

**SHIP v0.3.1 (merge to main, tag v0.3.0) if ALL hold:**
- LLM-verifier majority W-T ≥ OFF majority W-T **+ 5pp**
- Savings drop vs OFF **< 8pp** (the verifier costs a little; that's fine)
- cheap-tier p95 latency **< 2s**
- deterministic pass-rate **≥ 85%**

**PARK (keep v0.2.2 as ship) if:**
- W-T gain < 3pp (verifier not earning its cost) — then try threshold=2 or
  verify only on low classifier-confidence responses, re-run.

# v0.3.2 — Prefix caching gate (branch `v0.3.2-prefix-cache`, stacked on v0.3-quality)

Pure cost lever, quality-neutral. `gateway/router/prompt_cache.py` replaces the
crude `inject_prompt_cache` with provider-aware breakpoints: it tags the end of
the stable prefix (system + leading few-shot) with Anthropic `cache_control`,
but only when the prefix clears Anthropic's ~2048-token minimum. DeepSeek/OpenAI
cache automatically (we just never reorder messages). `drop_params=True` strips
`cache_control` for providers that don't support it, so mixed tiers are safe.

The RAG / long-system-prompt rows in corpus_v1 (ids ~231-260) are where this
fires — the old corpus had none, which is why we never saw the win before.

## The gate

```bash
cd /workspaces/LLM
git fetch origin && git checkout v0.3.2-prefix-cache && git pull
cd gateway && docker compose up --build -d && sleep 90
pip install --user pytest-asyncio==0.24.0 2>&1 | tail -1
pytest -m unit -v 2>&1 | tail -10    # expect test_prompt_cache + test_verifier green

# Run the eval on the RAG-heavy slice (the long-system-prompt rows) twice:
#  - first call populates the provider cache, second should hit it.
# Easiest: run the full corpus once to warm, then again and read cache_read.
cd /workspaces/LLM
GATEWAY_URL=http://localhost:8000/v1 GATEWAY_KEY="$GATEWAY_MASTER_KEY" \
  ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  python3 scripts/eval_corpus.py --results scripts/eval_warm.jsonl   # warm
GATEWAY_URL=http://localhost:8000/v1 GATEWAY_KEY="$GATEWAY_MASTER_KEY" \
  ANTHROPIC_API_KEY="$ANTHROPIC_API_KEY" \
  python3 scripts/eval_corpus.py --results scripts/eval_hot.jsonl    # should hit cache

# Inspect: on the long-system-prompt rows, the gateway response usage should
# show cache_read_input_tokens > 0 on the hot run. Check the gateway logs:
docker compose -f gateway/docker-compose.yml logs gateway | grep -i "cache" | tail -20
```

## SHIP / PARK

**SHIP if:** on the RAG/long-system-prompt rows, input cost drops ≥ 40% on the
hot run, AND quality W-T is unchanged (prefix caching must not move quality —
if it does, something reordered messages or broke a call).

**PARK if:** any non-Anthropic row errors (means `cache_control` leaked through
drop_params) — then gate injection behind a per-tenant `prefix_cache=anthropic`
flag instead of injecting unconditionally.

Merge order once both gates pass: `v0.3-quality` → main, then
`v0.3.2-prefix-cache` → main, then tag `v0.3.0`.
